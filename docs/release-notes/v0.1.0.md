# v0.1.0

First tagged release of the SMA multi-tenant salon management platform. This
release delivers the full application on top of the project's requirements and
process documentation, built through the documented `feature/*` → `dev` → `main`
workflow.

## Added

- **Project foundation** — Next.js 16 (App Router) + React 19 + TypeScript scaffold, shadcn/ui design system, shared presentational components, and the API-handler / React Query core platform.
- **Multi-tenancy** — split `control` and per-tenant Prisma schemas, tenant provisioning and client resolution, host/proxy routing, and tenant CLI scripts.
- **Authentication** — customer and admin auth with JWT sessions, password hashing, email + OTP flows, and the customer account area.
- **Admin panel** — dashboard, settings, roles, and workspaces, with the shared admin shell (sidebar, topbar, charts).
- **Service catalog** — services, categories, staff, opening hours, salon settings, and the public catalog/availability APIs.
- **Booking engine** — public booking creation and reference lookup, admin appointment management, and refunds.
- **Payments** — pluggable payment provider registry (Stripe / none), admin payment-gateway and integration settings, checkout, and a tenant-scoped Stripe webhook.
- **Reviews** — customer review submission and admin moderation.
- **CRM & operations** — customer records and staff leave management.
- **Messaging** — contact form, newsletter subscription, and admin notifications.
- **CMS** — block-based page builder with renderers and registry, menus, media library with Supabase storage, and appearance settings.
- **Public storefront** — tenant public site with catch-all slug routing, navbar, and footer.

## Changed

- Replaced the placeholder repository README with a real project README documenting stack, structure, and workflow.

## Fixed

- **Stripe webhook idempotency** — the webhook now only confirms a still-`pending` payment, so at-least-once redeliveries can no longer re-confirm a refunded/cancelled booking. (#43)
- **Booking reference casing** — the public reference lookup normalizes (trim + uppercase) the reference before its case-sensitive query, fixing spurious 404s on lowercased input. (#45)

## Security

- Real environment files (`.env`, `.env.gcp`) remain git-ignored; only vetted `.example` variants are committed. Tenant database URLs and app secrets are encrypted/stored via Secret Manager, never as plain env vars.

## Documentation

- Kept the existing product / architecture / ADR / development / deployment / release-notes strategy docs, and added operational docs: deployment, GCP Cloud Run deployment, migrations, tenant provisioning, and adding a tenant.

## Deployment Notes

- **Docker:** `docker compose build && docker compose up -d` (see `docs/deployment.md`).
- **GCP Cloud Run:** copy `.env.gcp.example` → `.env.gcp`, then run the `scripts/ops/gcp/*` bootstrap scripts; CI deploy/migrate via GitHub Actions (see `docs/deployment-gcp.md`).
- Run `npx prisma generate --schema prisma/control/schema.prisma` before building (the generated control client is git-ignored).
